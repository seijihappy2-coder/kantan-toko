# 改善記録の運用ルール

版：1.0／2026-10-12

## 原本と役割

このファイルが、このリポジトリの改善記録ルールの原本です。READMEは入口、AGENTS.mdはAIへの指示、Obsidianは同じMDを読み書きする道具です。Obsidian側に別のルールを複製しません。別ツールへ規則を更新するときは版と変更理由を揃えて各リポジトリを更新します。共通規則の配布元は ai-monetize-compass の docs/operation-rules.md、各ツール固有の事情は下の「ツール固有の扱い」に記載します。

改善記録の原本は保存済みMDです。記録ページのブラウザー保存は入力中の下書きで、原本の自動同期ではありません。MDを書き出し、保存先を確認してから原本の更新が完了します。コードをGitHubへ送ってもブラウザー内の記録・SQLite・WordPress・Artifactのデータは移りません。改善記録はそれら本来のデータの代わりではありません。

## 保存場所

- records/improvements/：GitHubへ残せる改善記録。1件1ファイル。
- records/assets/：その記録で参照する、共有可能な画像や添付資料。
- records/private/：手元限定の記録。Gitでは無視します。
- records/assets/private/：手元限定の添付資料。Gitでは無視します。
- records/templates/improvement.md：入力ひな形。コピーして使います。
- docs/history.mdなど：コード開発の履歴。利用・効果の記録とは区別します。

ファイル名は YYYY-MM-DD_記録ID.md。日付は日本時間、IDは作成後に変えません。追記・修正は同じIDのMDに行い、変更前はGitのコミットで残します。未保存データを別のMDで置き換えません。出典・比較期間・確認日は本文に明記します。画像は assets/ の中に置き、MDから相対パスで参照します。リポジトリ直下をObsidianの保管庫として開くか、既存Vaultからこの records/ を読む運用にします。コピーした二つの原本を並行編集しないでください。既存のVault設定・同期・保存場所は勝手に変更しません。

## 記録に必要な項目

ツール・取り組み名、タイトル、日付、状態、公開範囲、課題、判断の理由、実施内容、改善前、改善後、確認結果、比較する数値、次の作業、出典・根拠、画像・添付資料。対象URLとコードのコミットSHAは分かる場合に記載します。分からないことは「未確認」と書き、数値や効果を創作しません。

状態は「計画中」「実施済み」「効果検証中」「効果確認済み」「保留」。実装したことと、売上・アクセス・作業時間が改善したことを分けます。「効果確認済み」には確認結果と根拠が必要です。比較する期間・対象・測定方法を揃え、因果関係を確認していない変化は「改善による効果」と断定しません。今後の希望・仮説・現在の実績も分けます。

## GitHubへ送る範囲

- private：手元だけ。records/private/ に置き、GitHubへ送りません。
- internal：本人がアクセスを管理する非公開リポジトリにのみ保存。
- public：公開してよいことを確認した記録のみ、公開リポジトリに保存。

パスワード、APIキー、認証用JSON、Cookie、メールアドレスなどの個人情報、健康記録、顧客の秘密、書籍の本文・ページ写真、購入教材の転載は含めません。非公開GitHubも秘密情報の保存先にはしません。公開範囲の欄だけではGitHubのアクセス制限は変わらないため、リポジトリの公開設定も確認します。機密性のある内容は、値そのものではなく「認証設定を修正し接続を確認」などの要約にします。

MDを書き出す前に内容確認のチェックを入れ、画像の画面内に認証情報・氏名・メール等が映っていないか確認します。このチェックは自動の漏えい保証ではありません。

## 作業の流れ

1. READMEから運用ルールを開き、最新の既存記録を読む。
2. 変更前の状態を、共有可能な画像・数値・出典とともに控える。
3. 小さな単位で改善し、表示・機能・保存を確認する。
4. 記録ページで記入するか、ひな形をObsidianで編集する。小見出しには###を使う。frontmatterの文字列は二重引用符で囲む。
5. MDを書き出して原本へ保存。以前の記録を上書きする前に差分を確認する。
6. 対象のMD・添付資料だけを選んでGitに追加し、差分を確認してコミット。GitHubへの送信・公開は利用者の指示された範囲で行う。git add . による一括登録は避ける。
7. 効果検証後、同じ記録に期間と結果を追記し、次の作業を決める。記録ページへ戻すときは更新したMDを読み込む。同じIDの異なる下書きがあれば、先に書き出してから下書きを除き、原本を読み込む。

## バックアップと復旧

MDと添付資料をまとめてバックアップします。ブラウザー・DB・WordPressなど、本来のデータは従来のバックアップ方法も続けます。自動同期、自動Gitプッシュ、自動削除はこの仕組みに含みません。MDを読み込むときは形式・ID・URLを検査し、同じIDの異なる記録は黙って上書きしません。同期の競合は最新更新時刻だけで判断せず、変更内容を確認して解決します。

## ツール固有の扱い

CLAUDE.mdの生産者向け画面と公開・下書きの方針を維持します。改善記録ページは開発・管理側だけの別ページで、生産者のタップ数を増やしません。WordPressの記事・固定ページ・守るカテゴリーには今回の改修で触れません。利用者の名前・写真・合言葉はGitHubへ自動転記しません。
